# 简体中文文本复核记录

适用版本为 Steam Windows Build 21377206（游戏 1.8.5）。本轮相对首版实际改变了 264 行游戏文本，其中包括供脚本读取的键、界面标签和叙事正文。按相同索引比较固定社区版本，最终有 684 行新增或不同。行数以 Unity 文本资源中的物理行为单位，一条历史事件可能跨多行，一行也可能包含多条政策。

## 范围与方法

| 范围 | 本次核验 |
| --- | --- |
| 24 张资源表，共 4,426 行 | 从原版、固定社区版及最终构建分别提取，检查记录数、非空文本、解析分隔符、格式占位符、富文本嵌套和颜色参数、乱码、残留俄文字母、重复长译文。共有 1,031 个编号占位符。 |
| 英俄底本 | 大部分资源同时有英文和俄文。法国政党表的英文文件缺失，法国特质表的原英文槽内容不完整，两表使用俄文底本。脚本事件 `new_event_text_en` 在这版游戏中没有同名俄文表。国策脚本的英俄换行不同，标识按字段匹配。 |
| 长事件 | 对有对应英文、去掉标签后至少 85 字符的 1,321 行进行跨语种相似度排序。按相邻事件、分支结果和同表最相似原句复读异常。向量只保留长段的开头和结尾，用于安排审读顺序，不能判断史实或证明逐字准确。 |
| 人工复核 | 针对“五个不”事件的 4 个选项及结果、新疆领导人与结局、圭亚那与苏里南人物、土耳其与格林纳达政治事件、伊拉克战争结果、法国经济政策、德国统一条件和外交与结局按钮进行英中或英俄中对读。对国家表、三套人物特质、六张姓名表按清单浏览，重点抽查历史人物。其余长文主要经过程序筛查和异常抽读。 |
| 数据与字体 | 查原程序集对资格条件的计算，重读生成的程序集并解析国策及事件查询。两种内嵌黑体均覆盖这 24 表使用的全部 2,440 个非控制字符。 |

## 已确认并修正的问题

下列索引从零开始。原作内的架空事件、国名与政治立场按游戏设定呈现。

- 新疆结局 `new_texts_en[264–266]` 连续错移。原来“局势没有根本变化”会播出赛福鼎治下的长期发展，赛福鼎路线播出包尔汉路线，包尔汉路线又重复了艾尔肯路线。对照选人事件和结局正文后，恢复三段各自对应的叙述，统一人物选择、修正名称及结局中的人名。
- 土耳其事件 `Events_text_en[713]` 把军政府顶住抗议、继续执政，写成了美苏拒绝参与谈判。按英俄两份原文复原结局和两个政治实体的颜色。
- 事件脚本与国策脚本共有 25 个内部字典键被当作标题翻译。恢复 1 个事件键、24 个国策键并保留中文标题。原英文国策表还有 7 个别名与程序实际取值不一致，按同版俄文表中的固定标识对齐。另从翻译指令清单中移除针对国策键的 18 处替换。重新解析最终程序集，20 次国策查询（19 个不同键）和 1 次事件查询均与原版调用一致，且能命中对应文本表。
- 路线条件 `new_texts_en[161–165,804,815,821]` 区分华约、经互会、毛主义堡垒与外交声望。毛主义条件读取修正 6，原英语把“毛主义堡垒”写反。三条军力门槛的实际条件是陆军至少 250.0 或 300.0、舰队至少 50.0，且未直接参战。德国统一 `other_text_en[326]` 中，中美影响力之和等于苏联时也可触发，中国自身影响力达到 100.0 则可独立满足条件。
- 直接提款和秘密提款曾显示成同一项；现在分别标明预算增加 10 和 5。冲突数据说明补回每增加 5.0 进度所需付出的代价。状态标签、东非党派按钮和军事联盟名称已补中文。
- 印度结局误把民族救国阵线写成“联邦税务局”，把政治过渡安排说成税务部门意见。圭亚那选举把贾根胜选、丘吉尔为之担忧写成了丘吉尔自己胜选。法国事件遗漏了总统在 1982 年宣布暂停改革以及 1981 年设定的政策目标。三处均已根据上下文和俄文重译。
- 朝鲜战后地图曾直接显示“朝鲜半岛局势”、SRK 或 PRK 作为国名。按政体分支和相邻长名，改为“朝鲜国”“朝鲜社会主义共和国”“朝鲜人民共和国”。格林纳达事件清除了残留的俄文字母与人名原文；伊拉克事件纠正了“彻底胜利性失败”和“巴尔干复兴党”。同时修复了旧文本中不合规的颜色值和缺失的段尾换行标记。

## 怎样复核

在本游戏补丁的源码目录运行，路径参数可以是 `resources.assets` 或其所在目录。要执行程序集检查，请保留同一目录下的 `Managed/Assembly-CSharp.dll`。普通玩家使用安装入口的 `verify` 即可。维护者可在独立 Python 环境执行下列命令。三份输入依次为安装器保存的 Steam 原件、缓存中的 `1.8.5_output` 和已汉化的 `China_Data`。

```powershell
py -3 -m pip install UnityPy==1.25.4 dnfile==0.18.0 dncil==1.0.2
py -3 audit_text.py --original "原件目录" --community "社区缓存目录" --localized "China_Data" --check-assembly --json "audit.json"
```

严格检查报告为 **24 表、4,426 行、0 项错误**。额外提示包括 5 条单行表内的排版分隔差异、18 条富文本强调范围差异、177 条数字写法差异，以及 50 个纯拉丁片段。最后一组恰为 25 个脚本键和 25 个图标字段。数字提示包含年月、单位换算和型号连字符，人工筛查以影响玩法的条件和数值为先。还原演练后，所有 28 个原件指纹与清单相同，新增排版程序集已移除；再次安装与校验均通过。

可选的 `rank_text.py` 仅在本机进行长句排序。可在隔离环境安装 `numpy`、`onnxruntime` 和 `tokenizers`，将模型仓库中的 `tokenizer.json` 与 `onnx/model_quantized.onnx` 同放一个目录，再运行下例。报告只记录表名、行号和分数。[固定版本的多语种模型](https://huggingface.co/Xenova/paraphrase-multilingual-MiniLM-L12-v2/tree/2c4055b12046f11709e9df2c122e59ffbdc2f900)

```powershell
py -3 rank_text.py --original "原件目录" --localized "China_Data" --model "本地模型目录" --json "rank.json"
```

首次发行版的实机抽查覆盖启动器、主菜单、地图提示和经济页。本轮复核在独立安装副本执行，尚未在游戏中逐一触发所有地区路线、架空结局、DLC 与存档分支。部分长文仍保留外语人名括注、组织缩写及原作独有的党派名称。
